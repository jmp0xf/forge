# ADR-0036：未发布的旧 Evidence GC 目录残留安全失败并原样保留

- Status: Accepted
- Date: 2026-07-29
- Deciders: Forge maintainers
- Supersedes: ADR-0035（仅旧版目录残留自动迁移）
- Superseded by: None
- Depends on: ADR-0021, ADR-0035

## Context

ADR-0035 把 GC crash residue 从 `.forge-gc-quarantine-<digest>/object` 目录改为类目录中的
`.forge-gc-quarantine-<digest>` 普通文件，并要求暂时自动迁移旧目录。实现该迁移不能只做一次
`hard_link` 和删除：它还必须在 Unix 与 Windows 上分别固定旧目录与对象身份、证明 ACL 和内容
边界、限制总读取与复制量、处理跨卷或不支持硬链接的文件系统，并为每个中断点设计可判定且可恢复
的持久状态。否则迁移本身会成为绕过当前句柄约束、无界读取或丢失唯一副本的新路径。

Forge 当前是 `0.1.0-rc.1`、workspace 设置 `publish = false`，仓库没有发布 tag；旧目录布局也不是
版本化 machine contract。在已检查的开发状态中没有发现必须就地迁移的旧目录残留。为一种未发布、
未观察到的私有中间布局长期保留跨平台自动迁移，会显著扩大最敏感的删除与恢复面，并使正常 GC
更难审查和验证。

但不能把未知旧目录当成垃圾清理。它可能仍保存对象的唯一完整字节；最安全、信息损失最少的默认
行为是停止并保留现场，让维护者先备份再人工判定。

## Decision

- ADR-0035 的当前同目录普通文件 `Q` 状态机保持不变：只读扫描要求持锁恢复；持锁扫描在验证全部
  residue 后，继续自动执行 `Q -> O` 或删除与 `O` 同 identity 的重复 `Q`。
- 名称匹配 `.forge-gc-quarantine-<digest>` 的目录属于不受支持的旧私有布局。只读扫描和持锁 GC
  都必须在任何 residue mutation 前失败，并保持整个私有状态树字节与命名空间不变。
- 失败前仍验证该路径不是符号链接/重解析点，且是权限合格的私有目录。符号链接、权限放宽或其他种类
  继续按更具体的路径安全错误失败，不能借“旧布局”降低验证要求。
- 诊断必须明确区分两种情况：当前普通文件 `Q` 可以通过持锁操作自动恢复；旧目录 `Q` 不支持自动
  迁移，所有字节已保留，维护者应先备份私有状态并人工恢复原对象后再重试。
- Forge 不为旧目录执行自动删除、硬链接、复制、暂存或原地改写，也不输出会覆盖或删除数据的一键
  修复命令。
- 若发布后的真实用户状态需要自动迁移，必须基于观测样本、受支持文件系统矩阵、I/O 预算和完整
  crash-recovery 状态机新增 ADR；不能在普通修复中重新引入路径式迁移。

此决定只收窄未发布私有 crash residue 的兼容读取，不改变 Receipt、Evidence、log、GC report 或
其他版本化 machine contract。

## Consequences

### Positive

- 遇到旧目录时不会删除、覆盖或复制可能是唯一副本的数据。
- 正常 GC 保持单一的固定类目录 capability，不再携带第二套跨平台恢复协议。
- 只读与持锁行为可预测，诊断不会诱导用户反复运行一个无法处理旧布局的命令。
- 全量 preflight 后才开始 mutation，因而不会在发现旧目录前先恢复另一部分 residue。

### Negative / trade-offs

- 真正持有开发期旧目录残留的维护者需要备份并人工恢复，Forge v0 不提供自动迁移便利。
- 诊断可以说明安全边界和下一步，但无法在不知道对象来源与业务价值时替维护者选择删除或覆盖。
- 若未来出现已发布且规模化的旧状态，需要重新设计并承担一条有界迁移协议。

### Implementation constraints

- 旧目录检测必须发生在 `recover_evidence_gc_quarantines` 的全量扫描阶段；任何恢复或删除均在扫描
  成功后才可开始。
- 空目录、仅含 `object`、与原对象同 identity/同字节、内容冲突、未知子项和符号链接等形态都不得
  触发旧布局 mutation。
- 测试必须对失败前后私有状态树的命名空间、对象种类、字节和安全相关元数据快照做相等比较
  （不依赖访问时间），而不只检查一个路径仍存在。
- 当前同目录普通文件恢复、冲突保留、保留集合、引用闭包、预算和类间 durability barrier 保持
  原有测试覆盖。

## Rejected alternatives

### 保留通用自动迁移

跨平台正确实现需要固定目录能力、ACL/identity 复核、总 I/O 预算、确定性 staging、冲突矩阵和每个
崩溃窗口的恢复证明。为未发布且未观察到的私有布局承担这些永久复杂度，不符合最小可信迁移面。

### 发现旧目录后直接删除

空目录看似可删，但仅凭当前目录内容无法证明另一个中断步骤已持久化；对非空目录更可能删除唯一
对象。该策略破坏数据完整性，也会把未知状态误报为成功清理。

### 自动复制回原名但保留旧目录

复制需要新的大小/总量预算、权限与 durability 协议，还会制造两份身份不同但内容可能相同的状态；
中断后无法仅凭路径判定哪一份已验证。保留旧目录也意味着后续每次扫描继续歧义。

### 只在持锁 GC 中失败，只读扫描仍提示自动恢复

这会给出错误的恢复承诺，诱导用户重复执行写操作；两种入口必须对不支持的布局表达同一边界。

## Validation and revisit conditions

- Unix 测试覆盖 Receipt、Evidence、log 三类扫描，以及空目录、仅 `object`、原名与 `object` 同
  identity、内容冲突、未知子项和符号链接，并证明只读与持锁失败后私有状态快照不变；可移植的
  普通文件 `Q` 测试继续覆盖 Unix 与 Windows。
- 完整 runtime、workspace、fuzz 和 dogfood 验证必须继续通过。
- 只有发现真实发布状态、明确迁移需求，并能给出跨平台边界与 crash-point 证据时，才重新考虑自动
  迁移；届时用新的 superseding ADR 记录。
